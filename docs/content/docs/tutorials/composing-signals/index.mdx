In this tutorial you'll build the state layer for a text editor toolbar. Each control owns its state, the toolbar composes them into a single tree, and a text preview consumes that tree without knowing how the controls work.

## Testing state in isolation

Because each state module is a plain object of Signals, you can unit-test it without mounting React.

```ts title="align/state.test.ts"
import { initState } from "./state"

it("starts with left alignment", ({ monitor }) => {
  const { alignment } = initState()
  expect(alignment.read(monitor)).toBe("left")
})

it("updates alignment", ({ monitor }) => {
  const { alignment } = initState()
  alignment.write("center")
  expect(alignment.read(monitor)).toBe("center")
})
```

<Callout>How the `monitor` fixture is configured is covered in [Testing Signals](/docs/tutorials/testing-signals).</Callout>

## Wiring React components

The React components are thin: each receives the piece of state it needs as props.

`Align{:ts}` reads `state.alignment{:ts}` with [`useComputed`](/docs/api/use-computed) and writes it on click - that one `Signal{:ts}` is all it knows about.

<include lang="tsx" meta='title="align/index.tsx"'>./align/index.example.tsx#code</include>

`Font{:ts}` reads both `family{:ts}` and `size{:ts}` through a single monitor from [`useMonitor`](/docs/api/use-monitor).

<include lang="tsx" meta='title="font/index.tsx"'>./font/index.example.tsx#code</include>

`Toolbar{:ts}` doesn't know what's inside each state - it hands the right piece to each child.

<include lang="tsx" meta='title="toolbar/index.tsx"'>./toolbar/index.example.tsx#code</include>

`App{:ts}` creates the whole tree once: passing `initState{:ts}` itself to `useState{:ts}` lets React call it as a lazy initialiser.

<include lang="tsx" meta='title="app.tsx"'>./app.example.tsx#code</include>

`TextPreview{:ts}` is a consumer of the whole toolbar state: it reads Signals from two levels deep and re-renders only when those change.

<include lang="tsx" meta='title="text-preview.tsx"'>./text-preview.example.tsx#code</include>

## What you've built

- Three state modules that compose into a tree mirroring the component hierarchy
- State that needs no React to test
- React components that stay thin and re-render only when the Signals they read change
